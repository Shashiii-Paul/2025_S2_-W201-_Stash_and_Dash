# Stash_and_Dash

## Overview
**Stash_and_Dash** is a 3D multiplayer hide-and-seek style horror game developed as part of the **COMP602: Software Development Practice** course at **Auckland University of Technology (AUT)**.

The game takes place in an abandoned factory, where players are divided into two roles - **Hunter** or **Hunted**.  
- The **Hunter** must capture all Hunted players before the timer runs out.  
- The **Hunted** must survive until time reaches zero.

This project demonstrates teamwork and the application of **Scrum methodology**, **version control**, and **software engineering best practices** to deliver a playable game prototype.

---

## How to Play

### Controls

| Action | Key |
|--------|-----|
| Move | **W / A / S / D** |
| Jump | **Spacebar** |
| Sprint | **Shift** |
| Attack (Hunter only) | **Left Click** |
| Place Barrier (Hunter only) | **F** |
| Remove Barrier (Hunter only) | **Q** |
| Start Timer (Hunter only) | **R** |

### Win Conditions
- **Hunter Wins:** All Hunted players are eliminated before the timer ends.  
- **Hunted Wins:** Survive until the timer reaches zero.  
- **Spectator Mode:** Eliminated Hunted players become invisible ghosts that can fly around the map.

## Development Details

### Tools and Technologies
- **Unity** – Game engine used for 3D game development  
- **Mixamo** – Used for 3D character design and animation  
- **GitHub** – Version control and collaborative coding  
- **Trello** – Task management and Scrum artefacts  
- **Miro** – Sprint planning and retrospectives  

### Game Features
- 3D multiplayer gameplay in a warehouse environment  
- Randomized role assignment (Hunter or Hunted)  
- Barrier and attack mechanics for the Hunter  
- Timer-based gameplay and survival system  
- Ghost spectator mode for eliminated players

## Scrum Process Summary

| Sprint | Focus | Key Outcomes |
|--------|--------|--------------|
| **Sprint 0** | Project Setup | Team formation, backlog creation, and initial planning |
| **Sprint 1** | Core Mechanics | Environment setup, multiplayer movement, role system implementation |
| **Sprint 2** | Feature Expansion | Login, inventory concepts, communication systems, refined mechanics |
| **Extra** | Finalization | Testing, bug fixes, documentation, and presentation preparation |

### Definition of Done
- Code is peer-reviewed and fully tested  
- Follows coding standards and includes clear comments  
- Functions correctly and reliably across environments  

---

## Quality Assurance and Testing

- Manual playtesting on multiple devices  
- Frequent commits and version control via GitHub branches  
- Code review evidence (50–75 lines with comments and fixes)  
- Deprecated branches created for outdated code sections  

---

## Lessons Learned
- Strong communication is critical for smooth collaboration  
- Effective use of GitHub prevents version conflicts  
- Testing throughout development ensures stability  
- Scrum artefacts improve visibility of team progress and workload
